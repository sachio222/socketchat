# Changelog

Each release of socketchat has a section here. Version numbers follow [Semantic Versioning](https://semver.org): the first number changes when something stops working the old way, the second for new features, the third for fixes.

## Unreleased

### Fixed

- **Server errors on Windows**: a server that refuses the connection now reads "connection refused" on Windows too, the same as on macOS and Linux, and the message no longer ends in two full stops.

## 0.5.1

This release adds a list of the servers you use, mouse support, Tab completion for commands and a new color theme. It also fixes security problems that a review of Socketchat's code found. Apps and servers on 0.4.0 and 0.5.0 still work with 0.5.1; "Upgrading" at the end lists what changes for them.

### New

- **Servers**: the chat screen shows the open room's server next to its name, and `/details` names it. `/servers` lists every server your profile knows, numbered, with how many of your rooms are there and whether it is connected, could not be reached and why, or not tried yet. `/forget <number>` asks first, then deletes that server from your computer with its rooms, their messages and keys, rooms there that ended with messages you have not read, the joins waiting there, the invite links you made there, its certificate and your account key. The server is not told, so others still see you in its rooms until an admin removes you. From a terminal, `socketchat servers` and `socketchat servers --forget <number>` do the same, and `--yes` skips the question.
- **Mouse**: click a room in the Chats list to open it, click a panel to move to it, and scroll the messages, `/help`, `/invites` and `/details` with the wheel. Boxes have buttons along their bottom edge, such as Yes and No when Socketchat asks a question. While the mouse is on, hold Shift as you drag to select text (Option or Fn on a Mac). `/mouse off` gives the mouse back to your terminal, and Socketchat keeps the choice in your profile.
- **Tab completes commands**: in the message box, Tab completes a command that starts with `/`, and Tab or Shift-Tab steps through the matches when there are several. Matching commands show on the help line, `/theme` Tab cycles the color names, and a grey suggestion after the cursor shows what Tab would add; Right arrow accepts it. Tab still moves between panels for anything else.
- **Colors**: the chat screen has a new default look called phosphor, green on a near-black screen. `/theme classic` brings back the old colors, which use your terminal's own background, and `/theme phosphor` switches back. Socketchat saves the choice on your computer, and `SOCKETCHAT_THEME=classic` overrides it for one run. Phosphor uses exact colors when `COLORTERM` is `truecolor` or `24bit`, and 256-color approximations otherwise.
- **Invite message**: `/invite` copies an invite message as the invite box opens, and C copies it again. The message says to install Socketchat from https://socketchat.org and then run `socketchat join "socketchat://..."`, ready to paste into a terminal; the quotes keep the link whole in every shell. A line under the link says "Copying…" while the clipboard program runs, then whether the copy worked, and the screen keeps taking keys meanwhile. Socketchat copies with the computer's clipboard program (pbcopy, wl-copy, xclip, xsel or clip.exe) and asks the terminal to copy when there is none. The box still shows the bare link and its QR code. `socketchat join` and `/join` accept web links of the form `https://socketchat.org/join#socketchat://...` as well as the `socketchat://` link, and `socketchat invite` still prints only the `socketchat://` link.
- **Getting started**: the installer ends with the commands that start a server, join one and open the chat screen. `socketchat` on a computer with no profile prints the same steps and exits without an error.
- **Version and about**: the chat screen shows `socketchat` and its version at the right end of the bottom line, and drops it when the window is too narrow to keep the help text whole. `/about` shows the version, what Socketchat is, the project link and the license.
- **Checking a download**: every file in a release now has a GitHub build attestation, a signed record of the commit and the release workflow that built it. `gh attestation verify <file> --repo sachio222/socketchat_v4 --signer-workflow sachio222/socketchat_v4/.github/workflows/release.yml` checks one, as the README shows.
- **IPv6 in invite links**: an IPv6 address may be written in brackets, as in `socketchat://[2001:db8::7]:7444/j/...`.

### Changed

- **New rooms go where you expect**: `/new` makes the room on the open room's server, or on the newest server you joined when no room is open, and says which. `socketchat new` uses the newest server, and `--server <number>` picks another from the `socketchat servers` list.
- **Errors name the server**: a server Socketchat cannot reach is named, as in "Could not reach chat.example.com: connection refused.", with a pointer to `/servers` or `socketchat servers`. A dropped connection names its server too.
- **Message box**: the empty message box reads "What's on your mind? #Book club", naming the open room after a #.
- **Name**: the product is written Socketchat in the app and the docs; the command stays `socketchat`.
- **Busy servers**: a server checks a room change while it goes on answering everyone else's requests.

### Fixed

- **New rooms after a server stops**: new rooms used to go on the first server you joined, so once that server stopped, `/new` failed even after you joined another.
- **Long messages**: the chat screen wraps only the messages that can reach the window, so a room full of very long messages no longer slows every key press.
- **Late joins**: a join completed after the invite's 24 hours waits for the inviter to confirm it, instead of showing the invite as expired.
- **Sideways photos**: a JPEG keeps its orientation, so a photo taken sideways shows the right way up.
- **The chat screen on errors**: `/save ""` no longer closes the chat screen, and the terminal goes back to normal when the chat screen stops on any error, on a crash, or when the system asks it to stop on macOS and Linux (SIGTERM, or SIGHUP when the terminal window closes). A crash message prints after the terminal is back to normal instead of over the chat screen, and a crash while reading the keyboard ends Socketchat with an error instead of looking like a normal quit.
- **Setting up again**: if making a profile stopped part way, the next `socketchat join` moves what it left aside, renaming the files to end in `.unfinished-` and a time, says so, and makes a new profile. Socketchat never deletes a salt file. A salt file without its database stops `join` with a message that names it, and a profile whose salt file is missing says so instead of saying there is no profile.

### Security

These changes come from a review of Socketchat's code. Some of them run on the server and some in the app, so update both. [SECURITY.md](SECURITY.md) describes what each part protects.

- **Room changes**: apps refuse a room change from anyone outside the room and show a warning when one arrives. They also check admin rights themselves and refuse, with a warning, a change only an admin may make, such as removing someone or changing the admins, when someone else sent it. When the last admin leaves, each app checks the new admin against its own record of who joined when. The member list shows everyone in the room, and someone the app has no name for shows as "someone" with a short form of their key.
- **Joining with an invite**: the person who invited you shows as verified once their app confirms the invite from inside the room, which it does by itself the next time it connects; until then Socketchat says "Waiting for <name> to confirm this invite." Your own name, identity key and app version stay out of the room until that confirmation, and until then you cannot make invite links or start direct messages from that room. If the inviter cannot confirm it, your name stays hidden until you compare safety numbers with someone there and mark them verified. An invite link verifies only the person who joined with it.
- **Removing someone**: removing someone from a room, or their leaving it, cancels the invite links they made there and drops any join still waiting on those links. Socketchat apps no longer let anyone in through a link whose maker left the room, and someone who already used such a link hears from their app that it stopped working and needs a new one. A removed member's key cannot join the room again.
- **Connections before sign-in**: a server closes a connection that has not signed in within 60 seconds of connecting, whatever it sends. Until then it takes frames of at most 8,192 bytes from it, and all such connections together hold at most 8 MB of partly sent frames; `max_frame_before_sign_in` and `max_buffered_before_sign_in_mb` in `socketchat-server.toml` change the two sizes.
- **New accounts through room links**: the room links one account makes register at most 100 new accounts every two days; `max_accounts_from_room_links` changes the number. A link past that, or one made by someone with no account on the server, still brings the person into the room, but they need a server invite before they can start rooms or direct messages.
- **Storage limits**: a server keeps at most 200 MB of messages and 4,000 MB of files per room, 4,000 MB of files per member of a room, 100 people waiting to join a room, and 8,000 MB in all, of which files may use nine tenths; a new setting in `socketchat-server.toml` changes each one. Past a limit it refuses the message or the file with a reason, such as "this server is full", which apps show as an error. Someone redeeming a link into a room that cannot take them hears why from their own app, and the link stays unused. If an add is refused later, the inviter's app says so, once per link each time it runs. A full room still takes requests to leave and changes that only take people out, and removing someone deletes the files only they were waiting for. An upload that does not finish is deleted after 6 hours, or sooner when the same member starts a fourth while three are unfinished.
- **Server data directory**: on macOS and Linux a server keeps its data directory for its own account (0700 for folders, 0600 for files, the certificate and its key included), narrows a directory an earlier release made when it starts, and says so in one line on standard error. Deleting a room or a member's data also clears SQLite's write-ahead log, and a Welcome nobody fetched before its person was removed goes with the removal.
- **Photos**: Socketchat cleans a photo by writing a new copy with only what is needed to draw it, so location and device data also leave thumbnails, the second images some phones add, and anything stored after the picture. GIF images are cleaned too, keeping their frames, timing and loop count, and PNG and WebP photos lose their color profiles, as JPEG photos already did. HEIC, TIFF, camera raw, JPEG XL, JPEG 2000 and Photoshop files, and photos over 100 MiB, ask before sending, as videos do.
- **Saving files**: when more than one file in a chat has the same name, `/save` lists them and saves the one you pick by number, as in `/save beach.jpg:2`, and the status line names the person whose file you saved. On macOS and Linux, a download goes into a new file only your account can read, and the hidden part file a stopped download leaves behind is deleted the next time you save that file, once nothing has touched it for an hour. Saved names never start with a dot or name a Windows device such as `CON`.
- **Questions on the chat screen**: the boxes that ask about a new server certificate, a safety number match, or sending a video or a photo that cannot be cleaned take y only as the first key pressed, as the yes-or-no questions already did. Any other key answers no, and keys typed or clicks made before a box showed never answer it. The video or photo goes to the room that was open when Socketchat asked. A room you join while words wait in the message box or a box is open does not open by itself: the status line names it, and the room you were in stays on screen.
- **Pasting**: on macOS and Linux, a paste goes into the message box as text, with its line breaks shown as ↵, and nothing is sent or run until you press Enter. Text with a line break never runs as a command, and a command runs only when it starts the message box and has single spaces between its words. A command too long for the box shows its start and its end. The message box takes at most 16 KB, as much as one message carries, and says so when it cuts a paste or fills up. This needs a terminal that marks pastes (bracketed paste), which most do.
- **Spaces in names**: Socketchat writes every name, room name and file name with one plain space between words, so a name sent with two spaces in a row, a tab or a full-width space can still be typed after `/kick`, `/verify`, `/dm`, `/admin`, `/rename`, `/switch` and `/save`. A name already kept with other spacing matches too.
- **`socketchat log` and `socketchat sync`**: the second and later lines of a message print indented by four spaces, so a line that starts at the left edge always begins a message and names the person who wrote it. Names and room names in this output are cleaned of control characters, as message text already was.
- **Server addresses in invite links**: Socketchat refuses an invite link whose server address is not a host name or an IP address, before it stores anything, and `socketchat server init` refuses such a `--host`. Server addresses in Socketchat's warnings and errors are cleaned of control characters.
- **Profile folder**: on macOS and Linux, Socketchat keeps your profile folder for your own account (0700 for the folder, 0600 for its files). When it opens a folder made by an earlier release, it narrows the folder and its files and says in one line what it changed. On a drive that cannot change these settings, such as a FAT or exFAT drive, it warns and opens the profile anyway. It will not open a profile folder that another user account owns, and says why. A profile folder reached through a link is checked where the link points.
- **Empty passphrase**: Socketchat no longer makes a profile with an empty passphrase. A `SOCKETCHAT_PASSPHRASE` that is set but empty stops `socketchat join` with a message before it makes anything, and one that is not valid text is refused everywhere.
- **Passphrase hashing**: new profiles turn the passphrase into a key with Argon2id at 64 MiB of memory, 3 passes and 4 lanes, up from 19 MiB and 2 passes, so each guess at the passphrase of a copied profile takes about five times the computing and over three times the memory. A Raspberry Pi Zero 2 W should still open a profile in under about 2 seconds.
- **Prebuilt programs**: the `socketchat` program in a release leaves out code that only the tests use, and the release workflow checks for it before publishing. Release builds use a pinned Rust version, 1.98.1, and the exact library versions in `Cargo.lock`.

### Upgrading

- **Update the server and the apps.** Apps and servers on 0.4.0 and 0.5.0 keep working with 0.5.1, whose protocol is unchanged, and some of the protections above need both sides on 0.5.1.
- **Server addresses that are not ASCII**: 0.5.1 apps refuse an invite link whose server address is not ASCII, so a link that 0.5.0 accepted with a name in another script no longer works. Write such a name in its `xn--` form in `public_host`. A 0.5.1 server warns about this when it starts, and still starts. Members who joined through such a link keep that address on their computer, so their 0.5.1 apps make no invite links there and say why. After changing `public_host`, send each of them a new server invite so they can start new rooms there; rooms they joined through the old address still cannot make links.
- **Profiles from earlier releases** keep their Argon2id settings, 19 MiB and 2 passes, and open as before. Apps on 0.4.0 and 0.5.0 also open profiles that 0.5.1 makes.
- **A profile made with an empty passphrase** by an earlier release still opens with an empty one, and Socketchat warns each time that it has no passphrase.
- **Pastes on Windows** still arrive as typed keys, one line at a time, so each line is sent or run as you would type it.
- **Invite links whose maker left**: a link stops working once the member who made it leaves the room or is removed. Ask someone still in the room for a new one.
- **Requests before sign-in**: a request over 8,192 bytes sent before signing in, which an app sends only when the server no longer knows any of its keys, now drops the connection instead of getting a refusal.
- **Server disk space**: `max_stored_mb` is a fixed 8,000 MB by default. On a larger disk, raise it in `socketchat-server.toml`, or apps hear "this server is full" at 8 GB.
- **Forgetting a server**: a room that ended for you before this update, with messages you have not read, stays after you forget its server until you read it or 30 days pass.
- **Saved files**: on macOS and Linux a saved file is readable only by your account. To share one from a shared or web-served folder, change its permissions after saving.

## 0.5.0 - 2026-10-21

This release lets you move between rooms, rename them and close them, deletes a room's history from your computer once you are done with it, and lists the invite links you made that still work. Apps and servers on 0.4.0 still work with 0.5.0.

- **Moving between rooms**: `/switch` opens another room, and Tab completes its name. Unread counts stay right after you close and reopen the app, and `socketchat log` marks the messages it prints as read. When more are unread than it prints, it prints the oldest unread ones first. Anything you had before this update counts as read.
- **Renaming a room**: admins rename a room for everyone with `/title`, and the room shows who renamed it.
- **Closing a room**: `/close` asks to close a room for everyone, and the room closes once its admins agree: every admin when the room has up to three, more than half of them when it has more. A room with one admin closes at once. `/keep` says no, and a request to close stays open for seven days.
- **Room details and muting**: `/details` shows a room's admins, how many people are in it and when it was made. A server on 0.4.0 cannot say when, so that line is left out. `/mute` hides a room's new-message count on your own computer, nobody else sees that you muted it, and `/unmute` shows the count again.
- **Leaving, removal and closing**: when you leave a room, socketchat deletes the room's keys from your computer at once. When you are removed or the room closes, it deletes them as soon as your app learns of it, which for an app that was not running is its next sync with the server. When you leave, the room's messages go at the same time, and `/leave` first shows any new messages and asks you to type `/leave` again. A room you were removed from or that closed stays on screen, saying so, and its read messages go when you open another room or quit. Unread messages stay until you read them and still show who wrote them. Once 30 days have passed since the room ended for you, socketchat deletes them anyway the next time it opens, you open another room or it quits.
- **Deleting data on your computer**: `/clear` deletes a room's messages and its files list from your computer while you stay in it. socketchat turns on SQLite's `secure_delete`, so deleted rows are overwritten inside your encrypted profile. A join request made with 0.5.0 no longer leaves spare keys on your computer once you join. Opening 0.5.0 deletes the history of rooms you left with 0.4.0.
- **Invite links you made**: `/invites` lists the ones that still work, and `/cancel <number>` stops one. From a terminal, `socketchat invites` lists them, and `socketchat invites --cancel <number>` stops one and names the link it cancelled.
- **Servers delete rooms nobody is in**: a 0.5.0 server deletes everything it holds for a room at once when a 0.5.0 app leaves it as the room's only member, as happens at the end of a close. Its hourly sweep also deletes rooms that have no members.
- **Working with 0.4.0**: apps and servers now use protocol 2, and still use protocol 1 with apps and servers on 0.4.0. A 0.5.0 server serves apps on 0.4.0, so you can update the server first. A 0.5.0 app works with a server on 0.4.0. A feature that needs a newer server says so and leaves the rest of the app alone.
- **Messages from add-ons and other programs**: rooms now carry them, end-to-end encrypted like text. One that carries a summary line shows it in the chat, and apps on 0.4.0 skip them. Each app also tells its rooms which version it runs.
- **Contributors**: `sh scripts/crate-age-check.sh` keeps libraries released less than 30 days ago out of `Cargo.lock`, so this release builds against older versions of some of them.

## 0.4.0 - 2026-10-20

The first release of socketchat v4: a rewrite in Rust of the earlier Python versions, with standard group encryption and a server you run yourself.

- **Group chats encrypted end to end with MLS** (RFC 9420, through OpenMLS 0.9.1), on the hybrid post-quantum suite ML-KEM-768 with X25519 by default. The suite comes from an IETF draft that is not final; [SECURITY.md](SECURITY.md) explains what that means.
- **Invite links** with no usernames or directory. A link works once, expires after the time the server sets (24 hours unless changed), and lets the new person check who invited them.
- **Verification**: safety numbers to compare in person, with a QR code.
- **A server that cannot read**: it checks signed group changes and admin rights, stores only encrypted data, and keeps no record that ties one person's groups together.
- **Files, photos and videos**, encrypted in chunks with a fresh key per file. Photos lose their location and device data before sending; videos ask first, because they keep theirs.
- **A terminal chat screen** that works at 80 by 24 and over SSH, with commands for invites, direct chats, files, verification and admins.
- **Encrypted local storage** keyed by your passphrase, locked so only one copy of socketchat opens a profile at a time.
- **A server built to face the open internet**: every connection has a memory budget, idle and silent connections are closed, large backlogs come back in pages, and a server that is full says so. Three rounds of security review went into this release.
- **One-line installers** for macOS, Linux and Windows. The Linux programs run on Intel and AMD machines and on 64-bit ARM, which includes a Raspberry Pi 4 or Zero 2 W.
